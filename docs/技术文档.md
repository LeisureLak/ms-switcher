# MouseSpeedSwitcher 技术文档

> 更新日期：2026-09-06（v2：现代原生 Win32 架构）
> 配套阅读：[踩坑记录](踩坑记录.md)、[性能基线](性能基线.md)、[README](../README.md)

## 1. 项目概述

Windows 后台工具：按 `VID:PID` 规则在特定鼠标（如轨迹球）插入时自动切换系统指针速度，拔出时恢复。托盘图标提供内嵌滑动条的弹出菜单，可实时调速、管理规则、开关开机自启。

- 语言：**Rust**（edition 2024）
- UI：**原生 Win32**（GDI 自绘 + `msctls_trackbar32` 真滑块 + DWM 圆角/暗色）
- 托盘：**`Shell_NotifyIconW`**（NOTIFYICON_VERSION_4）
- 设备监听：**`RegisterDeviceNotificationW` + `WM_DEVICECHANGE`**（350ms 防抖）
- 系统速度变化：**`WM_SETTINGCHANGE`**
- Win32 调用：**windows 0.62** crate（不依赖 eframe/egui/glow/winit/tray-icon）
- 目标平台：Windows 10/11，普通用户权限

实测（Release，空闲 60 秒）：总工作集 **≈10.8MB**、私有工作集 **≈1.2MB**、
**1 个线程**、累计 CPU **≈31ms**。菜单打开状态约 2.3MB Private Bytes。
（旧 egui 版为 114MB / 9 线程 / 2672ms，详见[性能基线](性能基线.md)。）

## 2. 功能清单

| 功能 | 说明 |
|---|---|
| 规则自动切换 | 插入命中规则的设备 → 应用规则速度（含可选滚轮速度）；拔出 → 恢复插入前速度；多个规则设备并存时**最后插入的生效** |
| 托盘菜单 | 左/右键点击弹出；标题行（指针速度 + 「恢复默认」=指针 10 · 滚轮 3（Windows 默认））、指针 Trackbar（1–20，**松手才应用**，拖动中标题显示灰色预览值）、滚轮行 + 滚轮 Trackbar（1–100 行/齿，同样松手才应用）、生效规则行、设备列表（当前生效者画对勾，已配置规则设备显示小齿轮图标）、开机自启、退出 |
| 设备子菜单 | 悬停设备行弹出独立小窗：VID/PID 信息、**指针/滚轮双滑块（本地预览，标签行实时显示档位）+「设为规则」按钮**（以滑块值写规则）、用当前速度保存规则、删除此设备规则（无规则时置灰）、重新应用规则 |
| 滚轮速度 | `SPI_GET/SETWHEELSCROLLLINES`（1–100 行/齿，全局）；规则可选 `wheel` 字段联动切换/恢复 |
| 滚轮模式 | 轨迹球特化：按住触发键（默认侧键1）期间 `WH_MOUSE_LL` 吞掉移动冻结指针，位移由 **Raw Input**（`WM_INPUT`/`RIDEV_INPUTSINK`，`lLastY` 相对位移）攒齿——不能用钩子的 `pt`，冻结光标后系统补偿事件会造成回弹（踩坑 四-17）；攒齿量经投递消息在消息循环侧 `SendInput` 注入 `MOUSEEVENTF_WHEEL`（回调内注入会自锁 win32k，见踩坑 四-16），松开恢复；触发键可在菜单录入（下一个**菜单外**的鼠标键），灵敏度 5–200 像素/齿可调；菜单打开期间整体放行 |
| 键盘 | ↑/↓ 移动焦点行，Enter/Space 执行，←/→ 调指针速度，Esc 关闭 |
| 开机自启 | HKCU Run 键，菜单内开关，切换后菜单保持打开 |
| 关闭方式 | Esc、失焦（点击菜单外任意处，AttachThreadInput 抢前台 + 菜单存活期 WH_MOUSE_LL 钩子兜底）、再次点击托盘图标；规则操作执行后自动关闭；关闭时前台焦点归还原窗口 |
| 按下反馈 | 所有命令区（恢复默认/开机自启/退出/子菜单操作与「设为规则」按钮）按下加深一档高亮，松手且未移出才触发 |
| 托盘图标 | 纯代码生成（深蓝圆 + 白指针），按 `SM_CXSMICON` × DPI 生成；`uFlags` 必须含 `NIF_ICON`；exe 图标由 `assets/icon.ico`（`tools/gen_icon.py` 生成）经 winresource 嵌入 |
| 托盘 tooltip | `鼠标灵敏度切换 - 指针: N · 滚轮: W · 生效规则: X (速度 M)`，仅文本变化才 `NIM_MODIFY` |
| 主题 | 跟随系统暗色模式（`AppsUseLightTheme`）；高对比度模式改用系统菜单色；Win10 上 DWM 属性静默降级 |
| 单实例 | 命名互斥体 `Local\MouseSpeedSwitcher_Singleton`，二次启动静默退出 |
| 托盘恢复 | 注册 `TaskbarCreated`，Explorer 重启后自动重新 `NIM_ADD` |

## 3. 模块结构

```
src/
├── main.rs            入口：PMv2 DPI、单实例、AppState 初始化、宿主窗口、托盘、消息循环
├── lib.rs
├── menu_model.rs      纯菜单模型（无 egui/Win32）：DevRow、布局常量与计算、
│                      行命中测试、悬停子菜单状态机、点击映射、键盘焦点、滑块夹取
├── scroll.rs          滚轮模式纯逻辑：TriggerBtn 触发键枚举、WheelAccum 像素→齿
│                      累积器、ScrollEngine 钩子侧运行时状态
├── state.rs           规则状态机（AppState）：插入/拔出/全量重扫/重新应用
├── devices.rs         SetupAPI 枚举鼠标类设备（实例 ID / VID / PID / 名称）
├── speed.rs           SPI_GET/SETMOUSESPEED（1–20）
├── config.rs          %APPDATA%\MouseSpeedSwitcher\config.json
├── autostart.rs       HKCU Run 开机自启
└── win32/
    ├── mod.rs
    ├── host.rs        隐藏宿主窗口、阻塞消息循环、HostState 所有权、
    │                  WM_DEVICECHANGE 防抖 / WM_SETTINGCHANGE / tooltip 同步
    ├── tray.rs        Shell_NotifyIconW 封装（RAII；NIM_ADD/SETVERSION/MODIFY/DELETE、
    │                  纯代码生成 HICON）
    ├── menu.rs        主菜单窗口：GDI 双缓冲自绘 + Trackbar 子控件（子类化转发 Esc）
    ├── focus.rs       菜单关闭时的前台焦点归还（Z 序找用户窗口 + AttachThreadInput 移交）
    ├── scroll_hook.rs 滚轮模式：WH_MOUSE_LL 常驻钩子（模式转换 / 吞移动冻结
    │                  指针 / 触发键录入）+ Raw Input 位移源（WM_INPUT）/ 滚轮注入
    ├── submenu.rs     设备子菜单窗口（WS_EX_NOACTIVATE，跨窗口悬停保持）
    └── device_notify.rs  鼠标接口设备通知（HDEVNOTIFY RAII）
```

分层原则：**纯模型（menu_model/state/devices/speed/config/autostart）不依赖任何
UI 或 OS 类型，可脱离窗口单测**；win32/ 只做消息 → 模型事件的映射与副作用执行。

## 4. 核心运行架构

### 4.1 单线程事件循环

```
main:
  SetProcessDpiAwarenessContext(PMv2) → 单实例互斥体 → AppState::new(加载配置+枚举设备)
  → Box<HostState>（唯一所有权）→ CreateWindowExW(隐藏宿主窗口, lpParam=&mut HostState)
  → RegisterDeviceNotificationW(GUID_DEVINTERFACE_MOUSE) → Shell_NotifyIconW(NIM_ADD)
  → GetMessageW 阻塞循环（无定时器、无轮询、无重绘）
```

- 宿主窗口是**真正隐藏的顶层窗口**（不 ShowWindow；不用 `HWND_MESSAGE`，否则收不到
  `WM_DEVICECHANGE`/`WM_SETTINGCHANGE` 广播）。
- 所有状态变化在消息循环线程内串行执行；无 `Arc<Mutex>`、无后台线程。

### 4.2 所有权模型（规避历史双重释放）

- `HostState` 由 main 的 `Box` 唯一持有；`CreateWindowExW` 的 `lpParam` 只传借用指针；
  `WM_NCCREATE` 只把指针写入 `GWLP_USERDATA`；窗口过程**永不** `Box::from_raw`。
- 菜单/子菜单窗口的 `GWLP_USERDATA` 存**宿主 HWND**（Copy 值，无所有权），经两跳
  反查 `HostState`（曾因混用两跳直接段错误，见踩坑记录 四-1）。
- HWND / HICON / HDEVNOTIFY / HFONT / 托盘注册状态全部 RAII（Drop 中 NIM_DELETE、
  DestroyIcon、UnregisterDeviceNotification）。

### 4.3 菜单生命周期

- **空闲**：只有隐藏宿主 HWND（0 个可见窗口，消息循环阻塞在 GetMessageW）。
- **打开**（托盘左/右键抬起）：刷新模型数据 → 创建 `WS_POPUP|WS_EX_TOOLWINDOW`
  主菜单（owner=宿主）→ 两个 Trackbar 子控件（指针 1–20 / 滚轮 1–100）→
  `ShowWindow` 后经 **AttachThreadInput 技巧抢前台**（托盘打开的弹窗直接
  `SetForegroundWindow` 常被前台锁静默拒绝，菜单从未激活则失焦关闭永远不触发）。
- **关闭**：先 `focus::restore()` 把前台焦点归还用户窗口（前台已是正常用户窗口则不动；
  否则按 Z 序取最上层 Alt+Tab 口径窗口，`AttachThreadInput` 附加到其线程后
  `SetForegroundWindow`——必须在 `DestroyWindow` 之前、本进程仍持前台时移交；
  找不到目标才退回 `NIM_SETFOCUS` 旧行为）→ 从 HostState 摘除 → `DestroyWindow`。
- **失活**：只 `PostMessageW(WM_APP_CLOSE_MENU)`，从不同步销毁（踩坑 三-3）。
- 子菜单：`WS_EX_NOACTIVATE` 不抢焦点（踩坑 三-4）；owner=主菜单，级联销毁。
  位置默认贴主菜单右缘，右缘出工作区时自动左翻，垂直方向夹取到工作区内
  （主菜单打开时也按「菜单+子菜单」全宽夹取，双保险）。

### 4.4 设备监听与速度同步

- `WM_DEVICECHANGE`（ARRIVAL / REMOVECOMPLETE / DEVNODES_CHANGED）→
  `SetTimer(350ms)` 一次性防抖（连发消息只保留最后一次）→ 到期一次
  `enumerate_mice()` + `AppState::apply_diff()` → tooltip / 菜单刷新。
- `WM_SETTINGCHANGE`：重读系统指针/滚轮速度；实际变化才同步滑块/菜单/tooltip；
  同时重读主题（暗色/高对比度）并刷新 DWM 边框。
- 程序自身 `speed::set()` / `speed::set_wheel()` 后立即更新内存状态，不等广播回环。

## 5. 关键技术要点

### 5.1 菜单绘制

- WM_PAINT 用内存 DC 双缓冲 + `BitBlt`（`WM_ERASEBKGND` 返回 1 禁系统擦除），整窗重绘不闪烁。
- 布局全部是 `menu_model` 里的 DIP 常量（320×`menu_height(n)`，行高 26 等），绘制时按
  `GetDpiForWindow/96` 换算物理像素；两阶段开窗（先 0 尺寸创建拿到真实 DPI 再定位定尺寸）。
- 字体：`CreateFontW("Microsoft YaHei UI")` 按家族名交给系统加载（含中文回退），
  高度按 `GetDpiForWindow/96` 缩放并随菜单开关创建/销毁；**不读取任何字体文件字节**
  （旧版整份 msyh.ttc ≈ +40MB 的根源）。
- 颜色：COLORREF 字节序为 **0x00BBGGRR**（`#0078D7` 蓝 = `0x00D77800`，曾搞反成橙色）。
- 高对比度：`SPI_GETHIGHCONTRAST` 检测，命中时全部改用 `GetSysColor` 系统菜单色。

### 5.2 滑块（真控件）

- 主菜单两个 `msctls_trackbar32`（TBS_HORZ|TBS_NOTICKS）：指针 1–20、滚轮 1–100；
  `WM_HSCROLL` 通知父窗口（lp = 子控件 HWND 区分，读 `TBM_GETPOS` = `WM_USER`）。
- **松手才应用**：`TB_THUMBTRACK`（拖动中）只更新模型预览值（标题行灰色显示），
  `TB_THUMBPOSITION`/`TB_ENDTRACK`（松手）才写系统；`TB_LINEUP` 等离散通知
  （方向键、点击滑轨）逐次直接应用。预览/提交逻辑在纯模型 `preview_*`/`commit_*`。
- 子菜单滑块是**本地预览值**（`model.sub_slider`/`sub_wheel`）：所有 `WM_HSCROLL`
  只改预览（标签行实时显示档位），点「设为规则」按钮才把两个值一起写入规则
  （`MenuAction::SetRuleWithSpeed(i, 指针, 滚轮)`）。
- build.rs 用 embed-manifest 嵌入 Common-Controls v6 清单，控件获得视觉样式（现代蓝滑块）。
- 子类化（`SetWindowSubclass`）转发 Esc/Q：滑块获得焦点后主菜单收不到键盘。

### 5.3 跨窗口悬停（主菜单 ↔ 子菜单）

- 悬停设备行 → 主菜单 `update_hover(Some(i))` → 打开子菜单；
- 指针进入子菜单：主菜单收 `WM_MOUSELEAVE`，模型按 `sub_pointer_inside` 保持；
- 指针移到子菜单的**滑块子控件**上：子菜单窗体收 `WM_MOUSELEAVE`，但光标
  仍在窗口矩形内 → 保持打开（不重挂 TrackMouseEvent）；滑块子类（id 3）
  自行登记 leave，从滑块直接移出窗口时投递 `WM_APP_SUB_LEFT`，宿主重查；
- 指针离开子菜单：置 `sub_pointer_inside=false`，若不在设备行上则
  `PostMessage(WM_APP_CLOSE_SUBMENU)` 异步关闭——处理时重新检查悬停状态
  （硬件消息先于投递消息，移回主菜单不会误关）。
- 100 次悬停进出循环回归：无死锁、无闪退、无孤儿窗口。

### 5.4 规则状态机（state.rs）

- `AppState` 持有 `active: Vec<(实例ID, Device)>`（按插入序）与
  `saved: 实例ID → (插入前指针速度, 插入前滚轮速度)`。
- 插入命中规则：记录**真实系统速度**（非内存值）→ `speed::set(规则速度)`；
  规则带 `wheel` 字段时同时 `speed::set_wheel`；拔出：恢复该设备记录的原速；
  若仍有其它规则设备在场，则应用其中最后插入者的规则速度（其 `wheel` 为
  None 时滚轮保持现状不动）。
- `effective_rule()` = active 中最后插入的规则设备（决定菜单勾选与 tooltip）。
- 同 VID:PID 的同型号设备共用规则；同型号两把设备靠实例 ID 区分插入顺序。

### 5.5 配置与持久化

- `%APPDATA%\MouseSpeedSwitcher\config.json`：
  `{ "rules": [ { "vid", "pid", "speed", "wheel", "note" } ], "scroll": { "enabled", "trigger", "px_per_notch" } }`；
  `wheel` 为可选字段（1–100 行/齿），旧配置缺省解析为 None = 规则不改滚轮；
  `scroll` 旧配置缺失时用默认值（关 / x1 / 40）。
- 解析失败回退默认配置；VID/PID 大小写不敏感匹配，保存时规范化为大写。

### 5.6 滚轮模式（WH_MOUSE_LL 常驻钩子 + Raw Input 位移源，scroll_hook.rs）

- **状态机**（钩子回调内，同线程借用 `HostState`，无锁）：录入态 →
  菜单外 `*BUTTONDOWN` 归类为 `TriggerBtn`（结果存静态量 + `WM_APP_SCROLL_CHANGED`
  通知宿主落盘/刷菜单，本次按下吞掉），菜单内点击 → 取消；激活态（按住触发键）
  → `WM_MOUSEMOVE` 全吞（冻结指针）；触发键抬起恢复；空闲态 → 仅匹配触发键按下。
- **位移源是 Raw Input 而非钩子的 `pt`**：功能开启时以 `RIDEV_INPUTSINK` 把
  宿主窗口注册成鼠标输入 sink，后台也收 `WM_INPUT`；`on_raw_input` 取
  `RAWMOUSE.lLastY` 相对位移（跳过 `MOUSE_MOVE_ABSOLUTE` 绝对坐标设备）进
  `WheelAccum` 攒齿（1 齿 = 120），`queue_wheel` 累积并投递
  `WM_APP_SCROLL_INJECT`（合并到一次泵周期一条），宿主在普通消息处理上下文
  `flush_pending_wheel` 一次性 `SendInput` 注入——**回调内绝不 SendInput**，
  否则线程自锁在 win32k（踩坑 四-16）。`pt` 不可用的原因见踩坑 四-17：
  它是光标位置而非原始位移，冻结光标后系统生成拉回真实位置的补偿移动，
  会被差分成反向位移 → 反向滚轮 → 滚动回弹。
- **注入事件自识别**：`LLMHF_INJECTED` 标记一律放行，防止吞掉自己发的滚轮。
- **菜单打开期间整体放行**（`set_menu_open` 原子开关），侧键/左右键恢复正常语义；
  关闭菜单时顺带取消录入。打开菜单时顺带复位 `scroll.active`（触发键恰好按着
  时开菜单，抬起事件被放行路径吃掉，不复位会永久卡在滚轮模式里）。
- **灵敏度**：`px_per_notch`（5–200 像素/齿，越小越灵敏），由菜单第三条
  Trackbar 修改；Raw Input 是未加速的设备相对计数，与像素量级一致、跨
  DPI/多显示器恒定，无需换算。
- **已知限制**：管理员窗口收不到钩子事件；只读 RawInput/DirectInput 且不响应
  注入滚轮的游戏内无效；钩子回调必须极短（超时被系统静默摘除），故只做内存
  运算 + PostMessage 投递，落盘/刷菜单/注入全部经消息投递回宿主线程。
- 与菜单存活期的「点击外部关闭」钩子（host.rs）是两个独立钩子实例，系统按
  安装顺序链式分发，互不影响。

## 7. 历史架构变迁

1. **手写 Win32 自绘**：窗口所有权/激活时序/销毁级联连环坑（踩坑记录 三）。
2. **egui/eframe 0.36**：框架接管窗口管理解决问题，但固定成本 ~120MB、空闲 CPU 3.5%。
3. **现代原生 Win32（当前）**：带着踩坑记录 三 的强制规避措施回到 Win32——
   单线程所有权、失活只投递、RAII、纯模型单测——达到 10MB 级工作集与近零空闲 CPU。
