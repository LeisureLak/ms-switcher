# MouseSpeedSwitcher 技术文档

> 更新日期：2026-09-06
> 配套阅读：[踩坑记录](踩坑记录.md)、[README](../README.md)（使用说明）、[slider-feature-verification.md](slider-feature-verification.md)（历史文档）

## 1. 项目概述

Windows 后台工具：按 `VID:PID` 规则在特定鼠标（如轨迹球）插入时自动切换系统指针速度，拔出时恢复。托盘图标提供内嵌滑动条的弹出菜单，可实时调速、管理规则、开关开机自启。

- 语言：**Rust**（edition 2024）
- UI：**egui / eframe 0.36**（glow 后端）
- 托盘：**tray-icon 0.24**
- Win32 调用：**windows 0.62** crate
- 目标平台：Windows 10/11，普通用户权限

## 2. 功能清单

| 功能 | 说明 |
|---|---|
| 规则自动切换 | 插入命中规则的设备 → 应用规则速度；拔出 → 恢复插入前速度；多个规则设备并存时**最后插入的生效** |
| 托盘菜单 | 左/右键点击弹出；含滑动条区（1–20 实时调速 + 「恢复默认」=10）、生效规则行、设备列表、开机自启、退出 |
| 设备子菜单 | 悬停设备行弹出独立小窗：VID/PID 信息、用当前速度保存规则、删除此设备规则（无规则时置灰）、重新应用规则 |
| 生效标记 | 生效规则设备行画对勾，行文本带 `· 规则 N` |
| 滑动条 | 拖动即时生效（SPI）；外部（系统设置）修改会同步回菜单 |
| 开机自启 | HKCU Run 键，菜单内开关，切换后菜单保持打开 |
| 关闭方式 | Esc、失焦（点击菜单外任意处）、点击菜单外区域；设备规则操作执行后自动关闭菜单 |
| 托盘 tooltip | `鼠标灵敏度切换 - 当前指针速度: N · 生效规则: X (速度 M)`，随状态实时更新 |
| 单实例 | 命名互斥体 `Local\MouseSpeedSwitcher_Singleton`，二次启动静默退出 |

## 3. 模块结构

```
src/
├── main.rs        入口：单实例、状态/托盘/轮询线程初始化、eframe 启动、调试日志
├── app.rs         UI 层：MenuModel（纯模型，可单测）+ App（eframe App，副作用与窗口调度）
├── tray.rs        托盘图标（tray-icon crate）+ 程序图标生成（纯代码画圆 + 指针）
├── state.rs       规则应用状态机：设备插入/拔出/全量重扫/重新应用（AppState）
├── devices.rs     SetupAPI 枚举鼠标类设备（实例 ID / VID / PID / 名称）
├── speed.rs       系统指针速度读写（SystemParametersInfo SPI_GET/SETMOUSESPEED，1–20）
├── config.rs      配置读写（%APPDATA%\MouseSpeedSwitcher\config.json）
├── autostart.rs   开机自启（HKCU Run 注册表）
└── lib.rs         模块声明（同时作为 lib 供 src/bin/diag.rs 与单测使用）
```

核心分层：**纯逻辑（state/devices/speed/config/autostart）不依赖 UI**；UI 层（app.rs）进一步把「绘制与交互判定」抽成不接触 OS 的 `MenuModel`，`App` 只做副作用（调速、写配置、开合窗口、退出）。

## 4. 技术选型与理由

| 选择 | 理由 |
|---|---|
| egui/eframe 而非手写 Win32 | 前版本手写 Win32 自绘菜单在窗口管理上连环踩坑（详见[踩坑记录](踩坑记录.md)第三部分）。egui 接管窗口生命周期与 DPI，交互逻辑可脱离 OS 单测 |
| glow 而非 wgpu 后端 | 体积更小、老 GPU 兼容性好；本项目只画简单控件，不需要 wgpu |
| tray-icon 而非 Shell_NotifyIcon 手写 | 官方维护、事件走跨线程通道，免去托盘回调消息与窗口过程 |
| 设备轮询（2s）而非 WM_DEVICECHANGE | `RegisterDeviceNotificationW` 需要消息窗口；eframe 架构下不如直接周期性 `SetupDiGetClassDevs` 简单可靠，且不漏事件 |

## 5. 关键技术要点

### 5.1 菜单窗口生命周期

- 菜单是**常驻无框透明窗口**（`ViewportBuilder`：`decorations(false) + transparent(true) + active(false) + taskbar(false)`），`clear_color` 全透明。
- **空闲态**：窗口缩成 1×1 藏在 `(-32000,-32000)`——窗口保持可见是为了让 winit 消息循环持续跑，`App::logic`（eframe 0.36 在窗口隐藏/空闲时仍会以 `request_repaint` 唤醒调用）得以轮询托盘事件。
- **打开**：`GetCursorPos` → `MonitorFromPoint` + `GetMonitorInfoW` 工作区夹取（按「菜单+子菜单」全宽夹取，保证子菜单展开不出屏）→ `ViewportCommand::OuterPosition/InnerSize/Focus/WindowLevel(AlwaysOnTop)`。
- **关闭**：缩回 1×1 移回屏外，并 `SetForegroundWindow(GetShellWindow())` 把焦点交还外壳，避免隐形的窗口占焦点。
- 尺寸命令带去重（`cur_size` 比对），避免每帧重发。

### 5.2 设备子菜单 = 独立 viewport 窗口

- `Context::show_viewport_immediate` 每帧调用（不调用即销毁），创建真正的原生子窗口：尺寸 = 子菜单本身（180×104 逻辑点），位置 = 主菜单外框左上 + (MENU_W, 悬停行 top)，紧贴右缘、顶对齐悬停行。**没有任何预留背板**。
- 子窗口 `with_active(false)` 不激活：点击子菜单不抢焦点，主菜单的失焦关闭逻辑不受影响。
- **跨窗口悬停保持**：光标进入子菜单后主菜单收不到鼠标事件（PointerGone），子菜单每帧回报「指针在内」（`pointer.latest_pos().is_some()`）存入 `MenuModel::sub_pointer_inside`；主菜单侧判定：悬停设备行 → 开；指针在子菜单内 → 保持；两者皆无 → 关。

### 5.3 MenuModel 纯模型与合成输入测试

- `MenuModel::draw(&mut ui) -> Vec<MenuAction>` / `draw_submenu(ui, idx) -> (Vec<MenuAction>, bool)`：只依赖 egui 类型，产出动作枚举；`App::run_action` 统一执行副作用。禁用项置灰且不可点在模型层保证。
- 单测直接驱动 egui：`ctx.begin_pass(RawInput{ events: 合成指针事件, .. })` → 手工 `Ui::new(...)` 调用 draw → `ctx.end_pass()`，断言产出的动作。注意：**egui 命中测试使用上一帧注册的控件矩形**，测试需先空跑两帧预热；连续点击帧之间需插入空帧隔离点击状态。
- 无渲染器环境下 `end_pass` 返回的 `textures_delta` 未被应用，Drop 会 debug_assert——测试中需 `out.textures_delta.clear()`。

### 5.4 DPI

- eframe/winit 自动声明 Per-Monitor V2 并提供 `pixels_per_point`，全部布局用逻辑点，无手写 DPI 换算。
- 文本按当前 DPI 矢量光栅化，多显示器拖动自动重排。
- 中文字形：egui 内置字体不含 CJK，启动时运行时加载 `C:\Windows\Fonts\msyh.ttc`（微软雅黑）注册进 `FontDefinitions`，读取失败仅退化为方框不崩溃。

### 5.5 规则状态机（state.rs）

- `AppState` 持有 `active: Vec<(实例ID, Device)>`（按插入序）与 `saved: 实例ID → 插入前系统速度`。
- 插入命中规则：记录**真实系统速度**（非内存值，防外部改动丢失）→ `speed::set(规则速度)`；拔出：恢复该设备记录的原速；若仍有其它规则设备在场，则应用其中最后插入者的规则速度。
- `effective_rule()` = active 中**最后插入**的规则设备（决定菜单勾选与 tooltip）。
- `reapply()`：规则增删后从当前系统速度出发按插入序重算 saved 与生效速度。
- 同 VID:PID 的同型号设备共用规则；同型号两把设备靠实例 ID 区分插入顺序。

### 5.6 设备监听

- 后台线程每 2s `enumerate_mice()`（SetupAPI，`GUID_DEVCLASS_MOUSE` + `DIGCF_PRESENT`），与 `AppState::apply_diff` 对账增删。
- 设备列表变化 → 置位 `dirty`（菜单打开中下一帧刷新数据）并重算 tooltip 推送 channel；UI 每帧消费 channel，tooltip 变化才调 `set_tip`。

### 5.7 线程与锁

- 全局仅一个锁：`Arc<Mutex<Option<AppState>>>`。后台线程短临界区（枚举+对账）；UI 线程在菜单动作中加锁。其余跨线程通信全用 `AtomicBool`（`TRAY_CLICK`、`dirty`）与 mpsc channel。

### 5.8 配置与持久化

- `%APPDATA%\MouseSpeedSwitcher\config.json`：
  ```json
  { "rules": [ { "vid": "056E", "pid": "01C5", "speed": 4, "note": "ELECOM 轨迹球" } ] }
  ```
- VID/PID 大小写不敏感匹配，保存时规范化为大写。

## 6. 构建与测试

```bash
cargo build --release        # 产物 target/release/mouse-speed-switcher.exe（单文件）
cargo test                   # 纯逻辑单测 + 合成输入交互测试（不需要显示器/真实输入）
cargo run -p mouse-speed-switcher --bin diag   # 打印当前速度/配置/设备清单
```

调试环境变量：

| 变量 | 作用 |
|---|---|
| `MSS_DEBUG_MENU=1` | 启动即弹出菜单（自动化冒烟测试用，且跳过失焦自毁——锁屏环境焦点会被系统收回） |
| `MSS_DEBUG_SUB=1` | 配合上项强制展开设备 0 的子菜单（验证独立视口窗口） |
| `MSS_DEBUG=1` | 打开 log crate 输出（eframe/winit 内部诊断，打印到 stderr） |
