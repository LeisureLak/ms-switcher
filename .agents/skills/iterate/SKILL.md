# 软件迭代流程

严格按顺序执行：

1. **读文档**：先读 `docs/技术文档.md`（功能清单、架构、技术要点）。涉及疑难排查或历史决策时再读 `docs/踩坑记录.md`。
2. **泛读代码**：通读 `src/` 各模块的注释与结构，建立全貌——`app.rs`（UI 与窗口调度）、`state.rs`（规则状态机）、`devices.rs` / `speed.rs` / `config.rs` / `autostart.rs`（纯逻辑）、`tray.rs`（托盘）、`main.rs`（入口与线程）。
3. **理解需求**：结合第 2 步的全貌，明确用户需求的准确范围与影响面；有歧义先澄清再动手。
4. **精读**：只细读需求涉及的函数与相邻调用方。
5. **实现**：改动最小化，风格与周边代码一致；菜单交互逻辑的改动优先在 `MenuModel` 层实现并补合成输入单测（方法见技术文档 5.3）。
6. **更新文档**：行为、架构或踩坑有变化时，同步更新 `docs/技术文档.md`、`docs/踩坑记录.md` 及 README 对应段落。

完成标准：`cargo test` 全过，`cargo build --release` 成功；涉及 UI 需人工目验时提示用户，可用 `MSS_DEBUG_MENU=1` 自动弹菜单辅助检查。
