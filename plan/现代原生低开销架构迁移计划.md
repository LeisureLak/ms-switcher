# MouseSpeedSwitcher 现代原生低开销架构迁移计划

> 编写日期：2026-09-06  
> 目标平台：Windows 10/11 x64，普通用户权限  
> 实现语言：继续使用 Rust 2024 edition  
> 本文用途：供新的开发 session 在没有此前对话上下文的情况下直接执行

## 1. 背景与问题结论

MouseSpeedSwitcher 是一个后台托盘工具：根据鼠标 VID/PID 规则自动切换 Windows 指针速度，并通过托盘弹出菜单调速和管理规则。

当前 UI 使用 `eframe 0.36 + egui 0.36 + glow(OpenGL)`，托盘使用 `tray-icon`。程序为了接收托盘事件，常驻一个位于屏幕外的 1×1 OpenGL 窗口，并每 100ms 唤醒一次 eframe。程序还会把整份 `C:\Windows\Fonts\msyh.ttc` 读入 egui 字体系统。

当前机器上的 Release 实测：

| 测试对象 | 工作集 | 私有工作集 | Private Bytes |
|---|---:|---:|---:|
| 最小空 eframe + glow | 77.78MB | 39.77MB | 63.52MB |
| 完整程序，禁用微软雅黑 | 80.25MB | 40.90MB | 64.52MB |
| 完整程序，正常加载微软雅黑 | 120.50MB | 79.57MB | 103.05MB |

完整程序空闲 20 秒消耗约 703ms CPU 时间，等价于单核 3.51%，在 12 逻辑核机器上约占整机 0.293%。

结论：

1. 业务状态和规则逻辑只增加约 1～3MB，不是主要问题。
2. eframe、winit、OpenGL 上下文和显卡驱动是约 78MB 工作集的固定底噪。
3. 完整微软雅黑 TTC 及 egui 字体解析/缓存又增加约 40MB。
4. 仅优化字符串、容器或 release profile 无法达到目标。
5. 要稳定低于 50MB 总工作集并尽量接近 10MB，必须移除常驻 eframe/egui/glow。

## 2. 最终技术决策

采用“现代 Win32”架构，而不是 WinUI 3、WPF、WebView2 或另一个跨平台自绘框架：

- 继续使用 Rust。
- 继续使用微软官方维护的 `windows` crate。
- Win32 HWND 和消息循环负责生命周期与输入。
- `Shell_NotifyIconW` 负责系统托盘。
- `RegisterDeviceNotificationW + WM_DEVICECHANGE` 负责设备变化通知。
- `WM_SETTINGCHANGE` 负责系统指针速度变化通知。
- 原生 Common Controls、GDI/主题 API 负责轻量控件和绘制。
- DWM 属性负责 Windows 11 圆角、边框和暗色外观。
- 如果 GDI/原生控件不能满足视觉质量，才按需引入 DirectWrite；Direct2D 必须经过内存原型验证后才能引入。
- 所有绘制资源都延迟到菜单打开时创建，菜单关闭后释放。
- 空闲时阻塞在 `GetMessageW`，不进行固定频率 UI 轮询或渲染。

不选择 WinUI 3 的原因：Windows App Runtime、XAML 控件树和合成层有明显固定成本，Rust/XAML 集成不成熟，且系统托盘最终仍需 Win32 互操作，不符合 10～50MB 的目标。

不把微软新近出现的 `windows-window`、`windows-canvas`、`windows-reactor` 作为本次迁移的生产依赖。它们目前发布成熟度不足；本次直接使用已在项目中稳定使用的 `windows` crate。

## 3. 强制资源目标

使用 Release 构建，在正常桌面会话下测量。禁止通过 `EmptyWorkingSet`、主动 trim working set 等方式伪造数据。

### 3.1 内存

硬性验收门槛：

- 启动并空闲 60 秒后：总工作集 `< 50MB`。
- 菜单打开稳定后：总工作集 `< 50MB`。
- 连续开关菜单 20 次后：Private Bytes 相对首次稳定值增长 `< 2MB`。

优化目标：

- 空闲私有工作集 `<= 10MB`。
- 空闲 Private Bytes `<= 20MB`。
- 菜单打开时私有工作集 `<= 25MB`。

不要把 4GB 左右的 x64 虚拟地址保留量当成实际内存。必须同时记录：

- Working Set
- Working Set - Private
- Private Bytes
- Peak Working Set
- 线程数
- 句柄数

### 3.2 CPU

- 无用户操作、无设备变化时，60 秒累计 CPU 时间目标 `< 100ms`。
- 任务管理器长期显示应接近 `0.0%`。
- 不允许存在 100ms、1s、2s 之类的永久轮询。
- 只允许设备事件防抖的一次性 timer；可选兜底扫描不得高于每 60 秒一次，并应在验证事件通知可靠后评估是否完全删除。

### 3.3 功能和体验

必须保持现有全部功能：

- 单实例。
- 启动时枚举当前鼠标并应用规则。
- 插入规则设备时切换速度。
- 拔出时恢复插入前速度。
- 多个规则设备并存时最后插入者生效。
- 托盘左键和右键均可打开菜单。
- 当前速度 1～20 的滑块实时生效。
- 恢复默认速度 10。
- 展示当前生效规则。
- 展示设备名称、VID、PID、规则速度和当前生效标记。
- 保存规则、删除规则、重新应用规则。
- 开机自启开关。
- tooltip 随当前速度和生效规则变化。
- Esc、点击外部、失焦关闭菜单。
- 子菜单和主菜单之间移动时不闪退、不误关。
- 多显示器和 Per-Monitor V2 DPI。
- 菜单不进入任务栏和 Alt+Tab。
- Explorer 重启后自动恢复托盘图标。

### 4.1 原样复用或只做小改的模块

- `src/state.rs`：规则状态机。

- `src/bin/eframe_baseline.rs` 在迁移完成并记录最终基线后删除或改为原生基线诊断程序。

### 4.3 最终应移除的依赖

功能对等并通过测试后，从 `Cargo.toml` 移除：

- `eframe`
- `egui`
- `tray-icon`

评估并按实际使用决定是否移除：

- `log`

保留：

- `windows`
- `serde`
- `serde_json`

不为了替换这三个 UI 依赖而引入另一个大型 UI 框架。

## 6. 核心运行架构

### 6.1 单线程事件循环

主线程执行：

1. 设置 Per-Monitor V2 DPI awareness。
2. 创建命名单实例互斥体。
3. 加载配置。
4. 枚举当前设备并创建 `AppState`。
5. 创建隐藏的顶层宿主窗口。
6. 添加托盘图标。
7. 注册设备通知和 `TaskbarCreated` 消息。
8. 进入阻塞式 `GetMessageW` 循环。
9. 所有状态变化在同一线程内串行执行。
10. 退出时按逆序释放托盘、通知、菜单和窗口资源。

隐藏宿主窗口使用真正的隐藏顶层 HWND，不使用 eframe 的屏外 OpenGL 窗口。之所以不用 `HWND_MESSAGE`，是为了稳定接收面向顶层窗口的系统广播，例如 `WM_DEVICECHANGE` 和 `WM_SETTINGCHANGE`。

正常情况下不需要后台线程，因此不再需要 `Arc<Mutex<Option<AppState>>>`。

### 6.2 应用状态所有权

创建一个主 `App`/`HostState` 对象，由主函数中的 `Box` 唯一拥有：

- `AppState`
- 托盘状态
- 主菜单 HWND
- 子菜单 HWND
- 设备通知句柄
- 当前菜单模型
- 当前 tooltip 文本
- 防抖 timer 状态
- GDI 字体、画刷等 RAII 资源

将 `&mut HostState` 指针通过 `CreateWindowExW` 的 `lpParam` 传入，在 `WM_NCCREATE` 中写入 `GWLP_USERDATA`。

关键所有权规则：

- 窗口过程只借用指针，绝不执行 `Box::from_raw`。
- `Box` 始终由主函数唯一持有，并在消息循环和窗口销毁完成后只释放一次。
- 不在窗口过程里拥有或释放顶层状态。
- 每个 HWND 和 HDEVNOTIFY 只有一个明确 owner。

这直接规避历史版本发生过的窗口创建失败双重释放。

## 7. 托盘实现

使用 `Shell_NotifyIconW`：

1. `NIM_ADD` 添加图标。
2. 紧接着 `NIM_SETVERSION`，使用当前支持版本。
3. 使用应用私有的 `WM_APP + N` 消息接收托盘事件。
4. 处理左键和右键抬起，避免按下/抬起重复触发。
5. 更新 tooltip 时只有文本实际变化才调用 `NIM_MODIFY`。
6. 菜单关闭后调用 `NIM_SETFOCUS` 把焦点正确还给通知区域。
7. 注册 `TaskbarCreated`，Explorer 重启后重新 `NIM_ADD + NIM_SETVERSION`。
8. 正常退出时 `NIM_DELETE`。

使用当前纯代码生成的 32×32 图标，或改为编译进 exe 的 ICO 资源。不要引入 PNG 解码库只为托盘图标。

删除当前专门阻塞在 `TrayIconEvent::receiver()` 的线程。

## 8. 设备通知与速度同步

### 8.1 设备事件

首选方案：

- 对 `GUID_DEVINTERFACE_MOUSE` 调用 `RegisterDeviceNotificationW`。
- 宿主窗口处理 `WM_DEVICECHANGE`。
- 只关心到达、移除完成和可能影响设备集合的事件。
- 收到事件后启动或重置一个 250～500ms 的一次性 timer。
- timer 到期时只进行一次 `devices::enumerate_mice()` 和 `AppState::apply_diff()`。

设备插拔可能连续发出多个接口事件，必须防抖，不能每条消息都全量枚举。

如果测试发现某些蓝牙/HID 鼠标不触发 `GUID_DEVINTERFACE_MOUSE`，再评估：

- 同时注册 HID 接口通知；或
- 使用 `CM_Register_Notification`；或
- 保留 60 秒一次的低频兜底扫描。

不要未经实测就恢复 2 秒轮询。

### 8.2 系统速度变化

宿主窗口处理 `WM_SETTINGCHANGE`：

- 重新调用 `speed::get()`。
- 当前速度实际变化时更新菜单滑块和 tooltip。
- 菜单关闭时只更新 tooltip，不创建绘制资源。

程序自身调用 `speed::set()` 后可以立即更新内存状态，不必等待广播回环。

### 8.3 tooltip 去重

集中实现 `sync_tip_if_changed()`：

1. 从当前速度和 `effective_rule()` 生成候选字符串。
2. 与 `last_tip` 比较。
3. 仅变化时调用 `Shell_NotifyIconW(NIM_MODIFY)`。

不再使用无界 mpsc channel，不再每两秒创建和发送相同字符串。

## 9. 菜单 UI 方案

### 9.1 窗口类型

主菜单：

- `WS_POPUP`
- `WS_EX_TOOLWINDOW`
- 不进入任务栏/Alt+Tab
- 打开时置于前台并定位到托盘点击处
- 尺寸按设备数量动态计算
- 使用显示器工作区夹取位置

子菜单：

- 独立 `WS_POPUP | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`
- 显式记录与主菜单的关系
- 指针在主菜单设备行或子菜单内部时保持打开

菜单只在用户点击托盘时创建。关闭时销毁菜单 HWND 及其绘制资源，后台只保留宿主 HWND。

### 9.2 控件和绘制

第一实现优先采用系统已有能力：

- 滑块：`TRACKBAR_CLASSW`，范围 1～20。
- 点击行：优先使用可 owner-draw 的原生 Button 子控件，自动获得键盘和 UI Automation 基础支持。
- 文本：系统字体 `Segoe UI Variable`，不可用时回退 `Segoe UI` / `Microsoft YaHei UI`。
- 背景、边框、选中态：GDI + UxTheme/SystemColors。
- 图标和勾选：简单矢量路径或 GDI 线条。

不要读取字体文件字节。通过字体家族名让 Windows 字体系统负责加载和中文回退。

仅当 GDI/原生控件原型无法达到可接受视觉质量时，增加 DirectWrite。Direct2D 必须单独做内存基线，确认菜单打开时仍满足总工作集 `< 50MB` 后才允许合入。

### 9.3 现代 Windows 外观

Windows 11 上按支持情况调用 `DwmSetWindowAttribute`：

- `DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_ROUNDSMALL`
- `DWMWA_USE_IMMERSIVE_DARK_MODE`
- 合理的边框颜色

同时处理主题和高对比度变化。Windows 10 上自然降级，不因属性不支持而失败。

不默认启用 Mica/Acrylic。一个短暂菜单没有必要为持续模糊付出额外 GPU 和合成开销。

### 9.4 DPI

在创建任何 HWND 前设置：

- `DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2`

所有布局保存为逻辑 DIP，绘制或设置窗口尺寸时按窗口当前 DPI 换算。处理：

- `WM_DPICHANGED`
- `GetDpiForWindow`
- `AdjustWindowRectExForDpi`
- 建议矩形重定位

必须在 100%、125%、150%、200% 缩放下目验主菜单和子菜单。

### 9.5 输入和关闭规则

支持：

- Esc 关闭。
- 点击外部关闭。
- 主菜单真正失去前台后关闭。
- 上下键移动焦点。
- Enter/Space 执行动作。
- 滑块方向键调节。
- 鼠标 hover 打开设备子菜单。

严禁在 `WM_ACTIVATE`、`WM_KILLFOCUS` 或子菜单创建调用栈中同步 `DestroyWindow`。统一 `PostMessageW(WM_APP_CLOSE_MENU, ...)`，返回消息循环后再关闭。

关闭前检查新的前台/焦点窗口是否属于主菜单或子菜单，避免主菜单因子菜单创建或点击而误关。

## 10. 历史 Win32 风险的强制规避措施

`docs/踩坑记录.md` 记录了旧版手写 Win32 的三类严重问题。新实现必须逐条满足以下约束。

### 10.1 禁止同线程锁重入

- UI 窗口状态由单线程直接拥有，不用全局 `Mutex` 保护 HWND。
- 窗口过程内不得持锁调用 `DestroyWindow`、`SetWindowPos` 等可能同步重入窗口过程的 API。
- 纯业务状态不跨线程，因此不需要锁。

### 10.2 禁止 FFI 所有权重复接管

- `lpParam` 只传借用指针。
- `WM_NCCREATE` 只存指针。
- 窗口过程不执行 `Box::from_raw`。
- 主函数负责唯一一次 drop。
- 创建失败时 HWND owner 和状态 owner 分开处理。

### 10.3 禁止失活时同步自毁

- 失活仅投递关闭请求。
- 子菜单创建/销毁期间设置明确的过渡状态。
- 处理关闭请求时重新检查当前菜单状态和焦点归属。
- 子菜单使用 `WS_EX_NOACTIVATE`。

### 10.4 资源 RAII

为以下资源实现明确的 RAII wrapper 或集中释放路径：

- HWND
- HICON
- HFONT
- HBRUSH
- HDEVNOTIFY
- timer
- 托盘 NOTIFYICONDATA 注册状态

禁止依赖“进程退出时系统会清理”掩盖菜单反复开关造成的句柄泄漏。

## 11. 纯菜单模型与可测试性

当前 `MenuModel` 与 egui 绘制类型耦合。迁移时保留“模型与 OS 副作用分离”的优点，但移除 egui 类型。

建议纯模型包含：

- `DevRow`
- `MenuAction`
- 当前速度
- 生效规则
- 自启状态
- 当前 hover/focus 行
- 子菜单设备索引
- 菜单逻辑尺寸
- 行布局和 hit-test
- 操作项是否可用

Win32 层只负责把 `WM_MOUSEMOVE`、`WM_COMMAND`、`WM_HSCROLL`、键盘消息映射为模型事件，再执行模型产生的 `MenuAction`。

替换当前依赖 egui RawInput 的测试，至少覆盖：

- 菜单高度和设备行坐标。
- 设备行显示文本。
- 有/无 VID/PID 时规则动作可用性。
- 有/无规则时删除动作可用性。
- hover 主菜单设备行打开子菜单。
- 指针移入子菜单后保持。
- 指针离开主菜单和子菜单后关闭。
- 自启、退出、恢复默认动作。
- 滑块夹取到 1～20。
- 键盘焦点移动和执行动作。

纯模型测试不得创建真实窗口。

## 12. 分阶段实施步骤

必须小步迁移，禁止一次性删除当前可运行 UI 后再长时间补功能。

### 阶段 0：固定基线和验证脚本

1. 阅读 `docs/技术文档.md`、`docs/踩坑记录.md`、`README.md`。
2. 运行 `cargo test` 和 `cargo build --release`，确认迁移前全绿。
3. 保存当前 Release 内存、CPU、线程、句柄基线。
4. 明确任务管理器和 PowerShell 采样脚本的指标口径。
5. 记录当前菜单每项功能和关闭行为。

完成条件：有可重复的迁移前性能数据和功能清单。

### 阶段 1：抽离纯菜单模型

1. 将 `DevRow`、文本格式化、菜单动作、布局和交互状态从 egui 绘制中抽离。
2. 为新模型补充纯 Rust 单元测试。
3. 暂时让旧 egui UI 继续消费新模型，确保行为不变。

完成条件：旧 UI 仍可运行，纯模型不依赖 egui。

### 阶段 2：原生宿主与托盘原型

1. 增加原生隐藏宿主窗口和阻塞消息循环。
